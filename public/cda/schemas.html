Introduction

MERISE

La méthode et ses livrables

MERISE est la méthode. MCD, MLD et MPD sont les livrables qu'elle produit. Méthode française d'analyse et de conception née dans les années 1970, elle décrit comment concevoir une base de données en passant par trois niveaux d'abstraction successifs, du métier vers la technique.

Méthode
MERISE
Méthode d'analyse et de conception · France, 1970s
Produit 3 livrables successifs, du métier vers la technique
Niveau 1 · Conceptuel
MCD
Quoi ?
Modélise le métier, sans aucune considération technique. Entités et associations.
Niveau 2 · Logique
MLD
Comment ?
Traduit le MCD en tables relationnelles avec clés étrangères. Indépendant du SGBD.
Niveau 3 · Physique

01
Chapitre I

MCD

Modèle Conceptuel de Données

Le MCD représente les données métier sans aucune considération technique. Il décrit ce qu'est l'information dans l'organisation, indépendamment de tout SGBD.

Éléments fondamentaux

Élément Définition Représentation
Entité Objet du monde réel (Client, Livre...) Rectangle, nom MAJUSCULE singulier
Propriété Caractéristique d'une entité Dans le rectangle de l'entité
Identifiant Attribut qui identifie uniquement Souligné, préfixé # ou id
Association Lien entre entités Ellipse, verbe à l'infinitif
Cardinalité Participation min, max Près du lien entité-association

Les cardinalités

Notation Signification Exemple
0,1 0 ou 1 fois (optionnel, unique) Un employé a au plus 1 bureau
1,1 Exactement 1 fois (obligatoire) Une commande a 1 client
0,N 0 ou plusieurs fois Un client a 0 à N commandes
1,N Au moins 1 fois Une facture a au moins 1 ligne
⚠   Attention
Sens de lecture MERISE
Les cardinalités se lisent depuis l'entité vers l'association. C'est l'inverse d'UML où on lit vers la classe cible. Question piège typique du jury.

Exemple : bibliothèque

Des lecteurs empruntent des livres. L'historique doit être conservé, donc la date d'emprunt est portée par l'association elle-même (association porteuse).

Checklist MCD

  • Toutes les entités ont un identifiant souligné
  • Associations = verbes, entités = noms
  • Cardinalités sur les deux côtés de chaque relation
  • Aucune clé étrangère au MCD (FK = MLD)
  • Pas de doublons d'information (normalisation)

Chapitre II

MLD

Modèle Logique de Données

Le MLD traduit le MCD en tables relationnelles, toujours indépendamment du SGBD. C'est ici qu'apparaissent les clés étrangères et que les relations N:N deviennent de vraies tables.

Règles de passage MCD → MLD

N° Règle Transformation
1 Entité Devient une table. L'identifiant devient clé primaire (PK).
2 Relation 1:N La PK du côté « 1 » migre comme FK du côté « N ».
3 Relation N:N Création d'une table d'association avec PK composée des 2 FK.
4 Relation 1:1 FK du côté (0,1) vers (1,1), ou fusion des tables.
5 Association porteuse Les attributs rejoignent la table d'association.
✓   Mnémotechnique
« La clé migre du côté 1 vers le côté N »
L'entité côté N reçoit une colonne FK qui pointe vers l'entité côté 1.

PKPrimary Key  ·  FK Foreign Key  ·  PK/FK Clé composée
La relation N:N du MCD est devenue la table EMPRUNTER avec PK composée (idLivre, idLecteur, dateEmprunt).

Notation textuelle normalisée

Format souvent demandé en complément du schéma visuel.
LIVRE (idLivre, titre, auteur, isbn, anneePublication) LECTEUR (idLecteur, nom, prenom, email, dateInscription) EMPRUNTER (#idLivre, #idLecteur, dateEmprunt, dateRetour)

La PK est soulignée. Les FK sont préfixées par #. Ici, la PK de EMPRUNTER est composée de trois colonnes pour conserver plusieurs emprunts du même livre par le même lecteur à des dates différentes.

Checklist MLD

  • Chaque entité du MCD → une table
  • Chaque relation N:N → une table d'association
  • FK placées côté N pour les relations 1:N
  • Respect de la 3e forme normale (3FN)
  • PK et FK clairement identifiées dans la notation

Chapitre III

MPD

Modèle Physique de Données

Le MPD est l'implémentation concrète dans un SGBD précis (MySQL, PostgreSQL...). C'est le script SQL qui sera exécuté pour créer la base.

Ce qui apparaît au MPD (et pas avant)

Types SGBD-spécifiques
VARCHAR(50), INT, DATE, DECIMAL(10,2), BOOLEAN
Contraintes
NOT NULL, UNIQUE, DEFAULT, CHECK
Clés
PRIMARY KEY, FOREIGN KEY ... REFERENCES ...
Auto-increment
AUTO_INCREMENT (MySQL), SERIAL (PostgreSQL)
Actions référentielles
ON DELETE CASCADE / RESTRICT / SET NULL
Index
Pour optimiser les requêtes fréquentes

Script SQL — MySQL 8

gestion_bibliotheque.sql
-- Base : gestion_bibliotheque | SGBD : MySQL 8.0 CREATE TABLE LIVRE ( idLivre INT AUTO_INCREMENT PRIMARY KEY, titre VARCHAR(200) NOT NULL, auteur VARCHAR(100) NOT NULL, isbn VARCHAR(13) UNIQUE, anneePublication YEAR, dateAjout DATE DEFAULT (CURRENT_DATE), INDEX idx_auteur (auteur) ) ENGINE=InnoDB CHARSET=utf8mb4; CREATE TABLE LECTEUR ( idLecteur INT AUTO_INCREMENT PRIMARY KEY, nom VARCHAR(50) NOT NULL, prenom VARCHAR(50) NOT NULL, email VARCHAR(100) UNIQUE NOT NULL, dateInscription DATE DEFAULT (CURRENT_DATE), actif BOOLEAN DEFAULT TRUE ) ENGINE=InnoDB CHARSET=utf8mb4; CREATE TABLE EMPRUNTER ( idLivre INT NOT NULL, idLecteur INT NOT NULL, dateEmprunt DATETIME NOT NULL, dateRetour DATETIME DEFAULT NULL, PRIMARY KEY (idLivre, idLecteur, dateEmprunt), FOREIGN KEY (idLivre) REFERENCES LIVRE(idLivre) ON DELETE RESTRICT ON UPDATE CASCADE, FOREIGN KEY (idLecteur) REFERENCES LECTEUR(idLecteur) ON DELETE RESTRICT ON UPDATE CASCADE ) ENGINE=InnoDB CHARSET=utf8mb4;
💡   À commenter au jury
Justifie tes choix techniques
Moteur InnoDB (support des FK), encodage utf8mb4 (emojis, accents), RESTRICT sur ON DELETE (empêche de supprimer un livre encore emprunté), index sur les colonnes de recherche fréquente.

Checklist MPD

  • SGBD cible précisé (MySQL 8, PostgreSQL 15...)
  • Types adaptés : jamais d'INT pour un code postal français !
  • Contraintes (NOT NULL, UNIQUE, CHECK) définies
  • Index sur les FK et colonnes de recherche
  • Actions ON DELETE / ON UPDATE réfléchies, pas par défaut

Chapitre IV

UML

Diagramme de classes

UML est un langage de modélisation orienté objet. Le diagramme de classes est le plus demandé en CDA : il décrit les classes, leurs attributs, méthodes et relations. Ce n'est pas un MCD — il inclut méthodes, visibilités, héritage, interfaces.

Niveaux de visibilité

+
publicaccessible partout
–
privateclasse seule
#
protected+ sous-classes
~
packagemême package

Relations UML

Association
───────
Lien simple entre classes
Agrégation
◇───────
Losange vide — « a-un »
Composition
◆───────
Losange plein — « composé de »
Héritage
───────▷
Triangle vide — « est-un »
Dépendance
- - - - ▸
Utilise temporairement
Réalisation

Implémente une interface
✓   Mnémotechnique
Agrégation vs Composition
Losange vide : le tout disparaît, les parties survivent (université / étudiants). Losange plein : le tout disparaît, les parties aussi (maison / pièces).

Cardinalités UML

Attention, le sens de lecture est l'opposé de MERISE.
Notation Signification
1 Exactement 1
0..1 0 ou 1 (optionnel)
*   ou   0..* 0 à plusieurs
1..* 1 à plusieurs
n..m Entre n et m
⚠   Piège
Sens inversé par rapport à MERISE
En UML, la cardinalité se lit vers la classe opposée. En MERISE, elle se lit vers l'association. À savoir justifier à l'oral.

Exemple : bibliothèque en UML

Le même domaine, mais modélisé pour une application orientée objet. On voit apparaître l'héritage (Personne abstraite), la composition (Livre composé d'Exemplaires), et une association classique.

Checklist UML

  • Visibilité (+, –, #) sur tous les attributs et méthodes
  • Types de retour des méthodes précisés
  • Cardinalités sur toutes les associations
  • Bons symboles (losange vide vs plein selon l'intention)
  • Classes abstraites en italique ou avec «abstract»

Chapitre V

Les 5 erreurs

Ce qui fait tiquer le jury

Cinq erreurs reviennent systématiquement dans les dossiers CDA et sont immédiatement repérées par les membres du jury. Les connaître, c'est éviter de les commettre.

01
Confondre les cardinalités MERISE et UML
En MERISE on lit vers l'association ; en UML vers la classe cible. Le sens est inversé. Cette confusion conduit à inverser les cardinalités quand on passe d'un formalisme à l'autre.
02
Mettre des clés étrangères au MCD
Les FK n'apparaissent qu'au MLD. Au MCD, on a des associations — pas des colonnes techniques. Ajouter un champ « idClient » dans une entité COMMANDE au MCD est une faute classique.
03
Oublier les visibilités en UML
Un attribut ou une méthode sans +, – ou # devant est incomplet. C'est le premier détail que le jury va vérifier sur ton diagramme de classes.
04
Confondre agrégation et composition
Losange vide = parties indépendantes du tout. Losange plein = parties détruites avec le tout. Mélanger les deux montre qu'on n'a pas compris la subtilité de la relation.
05
Mélanger MLD et MPD
Pas de VARCHAR(50), AUTO_INCREMENT ou ENGINE=InnoDB au MLD. Ces détails n'apparaissent qu'au MPD. Le MLD reste indépendant du SGBD choisi.
